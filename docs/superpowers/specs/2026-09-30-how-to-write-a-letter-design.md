# How to Write a Letter: Content Design

## Decision

Create one English, evergreen informational guide for the primary query `how to write a letter`.

- **Decision:** GO, subject to post-publication measurement.
- **Audience:** English-language readers who need to write either a formal letter or a personal letter and are unsure about format, tone, or what to include.
- **Reader task:** Write an appropriate, complete letter by choosing the correct format and adapting a clear model.
- **Business role:** Organic education and discovery. The article must not force an unrelated product CTA because the current tool registry contains no dedicated letter-writing tool.
- **Scope boundary:** Explain general formal and informal letters, including email adaptation. Do not provide jurisdiction-specific legal notices, immigration letters, employment advice, or fabricated expert guidance.

## Evidence And Gaps

- Existing English drafts use a publishing-details block followed by a practical, example-led long-form guide. The new draft will follow that convention.
- The query is a broad, informational phrase. The intended content format is a comprehensive how-to guide rather than a product page or a thin template collection. This is an intent hypothesis because a reliable live US SERP sample was unavailable in this environment.
- Google Ads search volume, keyword difficulty, CPC, Search Console data, and a verified live SERP sample are unavailable. The draft must not make claims about demand, competitiveness, ranking prospects, or user behavior.
- No existing project URL appears to own this exact task. `content/blog-drafts` is the current pre-publication source location.

## Page Definition

- **Slug:** `how-to-write-a-letter`
- **Proposed title:** `How to Write a Letter: Formal and Informal Formats, Examples, and Tips`
- **Proposed meta description:** `Learn how to write a letter for formal and personal situations. Follow the right format, choose the right tone, and adapt clear examples.`
- **Visible H1:** `How to Write a Letter: Formal and Informal Formats, Examples, and Tips`
- **Primary page role:** Informational guide.
- **Internal link:** None is required in the initial draft. Add one only if a closely relevant first-party letter-writing resource becomes available.
- **Schema:** Do not add schema at draft stage. The publishing implementation may use `Article` markup only when it accurately represents the visible, maintained page.

## Article Structure

1. Give a direct definition of the shared parts of any letter and when a formal or informal format is appropriate.
2. Explain the formal-letter structure: sender details, date, recipient details, salutation, opening, body, closing, and signature.
3. Provide a complete formal-letter example with annotations that explain the choices.
4. Explain the informal-letter structure and the tone differences from a formal letter.
5. Provide a complete personal-letter example with annotations.
6. Cover email adaptation, including subject lines and when paper-letter conventions can be omitted.
7. Provide a practical final checklist and concise answers to common questions.

## Content Rules

- Put the primary query naturally in the title, H1, introduction, and only relevant headings.
- Lead every section with an answer, then show a concrete example or decision rule.
- Use invented names and situations only as clearly labelled examples; do not imply they are customer stories or real outcomes.
- Avoid fixed keyword-density targets, rankings promises, unsupported legal or business advice, and generic filler.
- Treat letter styles as conventions that vary by country, audience, and purpose; advise readers to follow any specified institution or employer requirements.

## Acceptance And Measurement

- The draft is a new Markdown file at `content/blog-drafts/how-to-write-a-letter.md` and matches the established publishing-details format.
- It contains one H1, descriptive H2s, both letter types, one complete example for each type, email guidance, and a final checklist.
- Metadata accurately represents the page and does not overpromise.
- Before publication, confirm the chosen URL does not duplicate an existing published page and validate title, description, headings, indexability, and any eventual schema in the publishing system.
- After 90 days of indexed availability, the content owner reviews relevant impressions, query mix, reader feedback, and qualified next-step behavior. Update the guide if it attracts the intended query but does not answer its dominant need; consolidate it if a more relevant existing URL emerges.
